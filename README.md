# NIKA PAY BOT

Закрытый Telegram-бот, который присылает уведомления о платежах магазина ЮКассы и считает аналитику.

## Что умеет

**Присылает сам**
- 💰 оплату: сумма, за что, способ (карта с банком и последними цифрами, СБП, SberPay), сколько придёт на счёт после комиссии, итог за сегодня
- ❌ отказ: причина по-человечески, кто отказал (банк или ЮКасса) и что с этим делать
- 🛒 брошенную оплату: без звука, это не ошибка, а потерянная продажа
- ↩️ возврат
- 🚨 тревогу: 3 отказа подряд в пределах часа (повторно только после успешной оплаты)
- 📊 итоги дня в 21:00 и итоги недели в понедельник в 10:00
- ночью с 23 до 8 всё приходит без звука

**По команде:** `/today`, `/yesterday`, `/week`, `/month`, `/last`, `/fails`, `/status`

Тестовые платежи помечаются 🧪 и не попадают в аналитику.

## Как устроено

Два источника событий:

- **Опрос API (основной).** Раз в минуту бот запрашивает в API ЮКассы платежи и возвраты за последние сутки. Нужен потому, что по платежам, которые создаёт Telegram, ЮКасса HTTP-уведомления в магазин не присылает. При первом запуске сутки истории записываются в базу без отдельных уведомлений, приходит одно сообщение-сводка.
- **HTTP-уведомления.** ЮКасса шлёт уведомление → бот проверяет IP отправителя → перезапрашивает платёж в API (защита от подделки).

Дальше событие сохраняется в Postgres и бот пишет тебе. Повторы отсекаются в базе, поэтому оба источника не дублируют друг друга.

Node.js 20+, grammY, Postgres. Сервер и бот в одном процессе.

## Запуск

### 1. Бот в Telegram
@BotFather → `/newbot` → получить токен. Это **новый** бот, EVENTS BOT не трогаем.

### 2. Ключ API ЮКассы
Личный кабинет ЮКассы → магазин, к которому подключён EVENTS BOT → **Интеграция → Ключи API** → выпустить секретный ключ. Там же виден `shopId`.

Без ключей бот запустится, но не будет ни опроса API, ни перепроверки уведомлений. Платежи через Telegram тогда не будут видны совсем. В `/status` будет предупреждение.

### 3. Railway
1. New Project → Deploy from GitHub repo (или `railway up` из этой папки)
2. Добавить в проект **Postgres**
3. В сервисе бота → Variables:
   - `BOT_TOKEN`
   - `OWNER_CHAT_ID` (узнать: написать боту `/start`, он ответит твоим chat_id; затем задать переменную и перезапустить)
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}`
   - `WEBHOOK_SECRET` = длинная случайная строка
   - `YK_SHOP_ID`, `YK_SECRET_KEY`
4. Settings → Networking → **Generate Domain**. Получится `https://<имя>.up.railway.app`

Проверка: открыть `https://<имя>.up.railway.app/health`, должно быть `ok`.

### 4. HTTP-уведомления в ЮКассе
Интеграция → **HTTP-уведомления**:
- URL: `https://<имя>.up.railway.app/yookassa/<WEBHOOK_SECRET>`
- события: `payment.succeeded`, `payment.canceled`, `refund.succeeded` (и `payment.waiting_for_capture`, если вдруг понадобится)

### 5. Проверка
После деплоя с ключами в течение минуты придёт сообщение «Подключил опрос ЮКассы» со сводкой за сутки. Затем сделать оплату: уведомление придёт в течение минуты. `/status` показывает время последнего события и последнего опроса API.

Тестовый режим Telegram («ЮKassa: тест» в BotFather) работает через **отдельный тестовый магазин**. Чтобы видеть тестовые платежи, HTTP-уведомления нужно включить и в нём, на тот же URL. Для перепроверки тестовых платежей через API понадобятся ключи тестового магазина, иначе на время теста можно не задавать `YK_SHOP_ID`/`YK_SECRET_KEY`.

## Ограничения, которые стоит знать

- **Кто именно заплатил, бот не знает.** Оплата идёт через встроенные платежи Telegram, ЮКасса видит карту, а не Telegram-пользователя. Связать можно: EVENTS BOT получает `provider_payment_charge_id`, это и есть id платежа в ЮКассе (в уведомлениях он внизу). Следующий шаг, если понадобится: EVENTS BOT пишет этот id и имя участника в общую базу.
- **Брошенные оплаты, скорее всего, почти не будут видны.** В платежах Telegram платёж в ЮКассе, по всей видимости, появляется только после ввода карты. Если человек открыл счёт и закрыл его, ЮКасса об этом не узнает. Как именно ведут себя отказы в связке Telegram + ЮКасса, проверим на первых тестовых оплатах (в тестовом магазине есть карты, которые специально получают отказ).
- **Неудачные попытки внутри одной формы** ЮКасса отдельно не присылает: приходит только итог.
- В ЮКассе на магазин один URL для HTTP-уведомлений. Если позже EVENTS BOT тоже захочет их получать, кто-то из двух должен пересылать другому.

## Файлы

```
src/index.js       запуск
src/server.js      приём вебхука, проверка IP
src/poller.js      опрос API ЮКассы раз в минуту
src/processor.js   очередь, перепроверка через API, сохранение, уведомление, тревоги
src/yookassa.js    IP ЮКассы, запрос в API, разбор платежа
src/format.js      тексты уведомлений, причины отказов
src/analytics.js   отчёты
src/commands.js    команды бота
src/scheduler.js   сводки по расписанию
src/db.js          Postgres, таблицы создаются сами
```
